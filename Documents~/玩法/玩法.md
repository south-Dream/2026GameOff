# PlaneShift 玩法文档

## 1. 游戏概述

PlaneShift 是一款第三人称空间解谜游戏。玩家在由道路、断桥、浮空平台和机关组成的立体箱庭中，通过压缩空间维度与操作场景机关改变道路连接，抵达目标区域并开启出口。

游戏采用 WASD 直接控制角色移动。玩家的主要行动包括观察地图、选择压缩方向、调整机关、沿道路前进，以及在目标平台恢复三维空间。

## 2. 核心玩法

玩家在三维地图中探索路线。面对高度差或水平距离造成的断路，可以选择对应方向进行维度压缩，使分离的道路在二维平面中连接。角色沿压缩后的道路移动，到达目标平台后展开空间，恢复至该平台的三维位置。

机关能够移动、旋转或升降道路，改变压缩后的路线。玩家通过组合机关状态与压缩方向，选择前进路径。

基本流程：

**观察地图 → 选择路线与机关状态 → 选择方向 → 按 Shift 压缩 → 沿路移动 → 按 Shift 展开 → 靠近出口 → 按 F 进入下一关。**

## 3. 控制方式

| 操作 | 功能 |
|---|---|
| WASD | 控制角色行走方向 |
| F | 靠近交互物后执行交互 |
| ← / → | 切换东、南、西、北观察方向 |
| ↑ / ↓ | 切换上方、下方观察 |
| 三维状态按下 Shift | 直接压缩空间 |
| 压缩状态按 Shift | 展开回三维空间 |

角色可以沿道路前进、回退、转弯和进入分支。方向键用于切换观察方向。角色移动受道路和场景碰撞限制。机关运动和空间切换期间暂停行走与交互，切换完成后恢复行走。

## 4. 视角与维度压缩

### 4.1 观察视角

游戏采用第三人称视角，提供上、下、南、北、东、西六个固定观察方向。压缩后，画面转换为对应的二维正交视图。

镜头在三维、压缩和展开过程中始终围绕角色，不以整张地图的中心作为跟随点。上下方向均从平台上方展示，压缩来源仍按玩家选择的观察面计算。

### 4.2 压缩方向

| 观察方向 | 压缩维度 | 保留平面 | 主要作用 |
|---|---|---|---|
| 上 / 下 | Y 轴高度 | XZ 俯视平面 | 消除平台之间的高度差 |
| 南 / 北 | Z 轴距离 | XY 侧视平面 | 消除平台之间的南北距离 |
| 东 / 西 | X 轴距离 | ZY 侧视平面 | 消除平台之间的东西距离 |

相反的两个观察方向对应同一种压缩维度，但观察面的近远顺序相反，重叠道路的来源可能不同。一次压缩只消除一个维度，其余两个维度的位置关系保持不变。

上下压缩后，角色在俯视道路中移动；水平压缩后，角色沿侧视道路移动。三维与俯视模式支持四向移动，侧视模式支持左右移动。

### 4.3 压缩范围

压缩作用于当前谜题区域内的道路、平台及指定机关。角色脚下的平台作为本次压缩的锚点。水域、虚空、远景和装饰不形成可行走道路。

参与压缩的结构使用统一的视觉标识。

### 4.4 压缩顺序

压缩从选定的观察面向内部进行。角色压缩前所在的道路始终最先保留，其余道路按面向该观察侧的近侧面由近到远排列，不按道路中心距离决定前后。近侧面相同时保留稳定顺序。

同一位置的重叠部分归属于先保留的道路。走出重叠部分、进入其他道路的独有区域后，当前落脚来源随之改变。上下压缩仍然消去全部高度差，前后顺序只决定来源归属。

## 5. 状态切换

### 5.1 三维探索

玩家观察地图、控制角色沿道路行走，并操作场景机关。不同方向能够展示道路的高度和水平距离关系。

### 5.2 直接压缩

按下 Shift 后立即按当前方向生成二维道路并切换碰撞与角色平面，不等待松键，也不提供 Esc 取消。镜头切换期间暂停移动和交互，过渡结束后进入二维行走。无法压缩时保留三维状态并显示提示。

### 5.3 二维移动

玩家使用 WASD 沿压缩后的道路移动。断口和障碍仍限制通行，角色不使用手动跳跃。需要更换压缩轴时，先展开回三维，再选择新的方向。

### 5.4 展开空间

角色在可恢复区域按下 Shift，回到当前道路对应的三维平台。展开位置受阻时保持二维状态，玩家可以移动至其他恢复区域。

压缩开始时保存角色所在道路与完整三维坐标。展开时仍在压缩起点所在道路，则恢复压缩前被消去的轴坐标，保留二维期间实际走过的坐标，不回到道路中心，也不退回整段移动前的位置。

展开时已换到另一条道路，则按新道路的当前位置计算深度：水平压缩取新道路的轴向中心，上下压缩恢复新道路顶面高度。原道路已站稳的轴向边缘位置可以保留，其他落脚范围与三维碰撞空间仍须有效。

## 6. 道路与空间规则

- 角色始终沿有效道路移动，不能跨越未连接的断路。
- 压缩只改变指定维度，保留平面中的距离与高度关系不变。
- 每段压缩道路对应明确的三维来源平台。
- 仍在原道路时保留压缩前的轴向坐标，换到新道路后重新计算展开深度。
- 重叠道路具有确定的归属，重复切换保持一致的空间结果。
- 上下压缩恢复来源平台的高度；水平压缩恢复来源平台对应的水平位置。
- 场景机关改变后的道路状态影响后续压缩与实际通行。

## 7. 地图样式

地图采用小型立体箱庭结构，以一条条有宽度的道路组成路线网络。道路分布于不同高度和水平位置，通过转折、分支、中继平台与机关形成连续的解谜区域。

整体呈现悬浮道路与机械结构组合的空间布局。开阔天空、云海或蓝色水域作为背景，浅色平台与清晰轮廓突出路线。可操作桥段、机关和目标物使用明确的颜色与形状区分。

| 地图元素 | 功能 |
|---|---|
| 道路与平台 | 角色移动、空间压缩与展开的基础 |
| 断桥与错位道路 | 构成距离和高度相关的空间谜题 |
| 中继平台 | 提供转向、展开和重新选择路线的位置 |
| 分支与回路 | 提供不同目标和机关操作顺序 |
| 机关节点 | 调整道路布局和通行状态 |
| 检查点 | 保存关卡进度 |
| 钥匙与出口 | 构成关卡目标 |
| 水域与虚空 | 表达地图边界与危险区域 |

地图以路线规划为核心。玩家能够提前看到部分目标，通过机关操作与空间变换逐步建立通路。

## 8. 机关与交互

机关与维度压缩共同改变地图路线。

| 机关类型 | 效果 |
|---|---|
| 平移桥段 | 改变道路位置，连接不同平台 |
| 旋转桥段 | 改变道路朝向，切换路线分支 |
| 升降平台 | 改变平台高度，调整侧视连接与展开位置 |
| 开关与门 | 控制指定道路或区域的通行状态 |

普通机关需要角色到达交互位置后操作。远程交互物使用独立标识。机关完成动作后，新的道路状态参与压缩。

初始 Demo 的机关在三维探索状态中操作。

## 9. 关卡设计

### 9.1 第一关：维度初识

第一关通过高度压缩、水平压缩和简单机关，建立基本空间认知。

1. **高度压缩：** 起点、中继平台和高处平台具有明显高度差。玩家压缩 Y 轴，沿俯视道路前往高处平台，展开后抵达高台。
2. **水平压缩：** 目标平台与高台存在较大的南北距离。玩家压缩 Z 轴，沿连接后的侧视道路抵达目标平台。
3. **机关组合：** 玩家操作桥段改变道路布局，再通过压缩连接出口路线。
4. **关卡完成：** 取得钥匙并开启出口。

### 9.2 后续关卡

后续关卡通过道路布局、机关状态和展开位置的组合增加变化：

- 俯视道路加入转折与分支，提供多个展开目标。
- 在不同平台展开后，选择新的方向继续压缩。
- 同一机关在不同状态下连接不同路线。
- 通过支路操作机关，再返回主路前进。
- 综合使用三个压缩轴，规划多阶段路线。

每个关卡逐步引入新内容，再与已掌握的机制组合。所有关卡保持一致的压缩与恢复规律。

## 10. 失败与重试

角色落入危险区域后返回最近检查点。检查点保存对应的关卡进度与机关状态。

无效移动、无法压缩和无法展开通过提示反馈，不扣除资源。玩家可以回退、重新观察和调整机关，继续尝试其他路线。


## 11. 关卡加载与推进

游戏使用单一 Game 场景，按顺序切换 Level 预制体包。每个包包含地图、角色、摄像机与环境，共用 UI 在切关过程中保留

加载完成后展示本关提示，关闭提示再开始操作。普通提示使用共用面板，特殊关卡可配置独立提示内容

出口通过接近交互显示提示条，三维状态下按 F 进入下一关；最后一关的出口显示完成旅程，交互后展示全部完成界面。二维状态需先展开，机关与镜头运动期间不能使用出口
